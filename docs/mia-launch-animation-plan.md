脚本默认末帧、工作流、提示词和外部交付包已同步当前半身星雾方向。只准备离线请求，没有提交新收费任务；正式启动视频、音画同步及与原生流光球的交接仍待后续审批和验收。

## 已确认分镜

约 5 秒、竖屏、一镜连续演绎。沿用[已选右侧第三款 Mia](design/README.md)和原半身角色，按批准的星雾首页构图制作。下沿雾在凝形前建立，并在结束后永久保留，不以淡出重新暴露水平切口。

| 时间 | 画面与动作 |
| --- | --- |
| 0–1 秒 | 原蓝紫细粒子云轻微呼吸、旋转，深蓝紫星雾渐显；粒子保持细密通透，不成胶状物。 |
| 1–1.6 秒 | 同方向旋转逐渐加速，粒子向人物下沿汇聚，建立有前后层次的暗紫雾；光流从此向上延伸。 |
| 1.6–2.8 秒 | 从下沿开始依次凝成裙腰、肩臂、脸发与晶体；各区域通过不规则光流重叠显现，不是整齐水平扫描，也不先出现孤立头部。 |
| 2.8–4.4 秒 | 身体凝形后头肩共同转向镜头，发梢与衣袖带少量残余粒子；近脸手划晶体光弧后收为 V，另一手向观众伸出。 |
| 4.4–5 秒 | 光弧落入无图标蓝紫粉流光球，角色姿态、尺度和星雾收束至末帧；最后约 0.3 秒稳定停留，永久下沿雾继续遮挡切口。 |

不使用硬切或闪白掩盖变形。粒子、转身和光弧保持共同的运动方向与蓝紫色系。5 秒生成素材可在合成时加入短暂首页衔接；不能靠加速拉伸掩盖角色动作问题。

## 最小接入范围

- `ios/MiaApp/MiaApp.swift`：持有一次冷启动的播放状态。
- `ios/MiaApp/MiaLaunchPlayback.swift`、`MiaLaunchView.swift`：本地静音视频、结束和失败处理、跳过、Reduce Motion、后台停止和资源释放。
- `ios/MiaApp/MiaLaunch.mp4`：验收通过后加入的成品；制作中不放入冒充成品的占位视频。
- `ios/MiaTests/MiaLaunchPlaybackTests.swift`：完成、跳过、失败、缺素材、辅助功能、后台与超时行为；使用测试包内的 16×16、2 秒静音 H.264 文件，不能用测试素材冒充成品。
- `.github/workflows/ios.yml`：首页截图等待启动完成，并保留模拟器启动录屏。
- `ios/README.md`、交接和路线图：分别记录使用方式、实际证据与待验项。

首页长期保留同一个 `ContentView` 和语音会话；覆盖播放期间阻止首页交互与无障碍焦点，退出覆盖后恢复。动画不请求麦克风、不启动音频会话、不连接服务器、不保存重播标记到用户设置。缺素材、播放失败或最长 7 秒无法完成时进入原首页。返回前台不重播。

## 下一次生成前的修正

生成工具：用户曾要求接入中国 MiniMax H3 API，独立[生成工具与使用说明](mia-minimax-video.md)已准备，默认 5 秒 768P；当前使用原粒子首帧和批准的半身星雾末帧。首尾帧与独立参考媒体互斥，实际比例自适应。初版 14 项离线测试通过；用户已在当前环境隐藏设置 MiniMax Key，权限 0600；配置后不存在任务查询返回 HTTP 500／`server_error`，随后真实创建已受理但素材读取失败。用户改为使用当前 Codex 工作环境，隐藏配置入口已就绪，已完成一次内嵌图片重试并输出预览，并按既定分镜验收，不把接入脚本当作动画成品。

用户曾选择自行在其他平台生成，已整理[外部生成交付包](design/launch/mia-launch-external-generation-brief.md)，其当前首末帧、参考图、主提示词、负面提示词与输出要求也已同步批准的半身星雾版本。OpenArt 后续报价只保留为候选记录，不继续生成；无论在哪个平台制作，正式视频收到后仍须检查角色、动作与 App 衔接。

2026-10-04 再次只读查询：OpenArt 账户为免费方案、0 积分；既有任务只暴露一个视频，没有无水印下载变体，MCP 没有视频编辑或无水印导出接口。官方[条款第 4.5 节](https://openart.ai/suite/terms)要求免费生成输出保留水印，除非生成时具备相应付费权益或另获平台许可。该查询没有提交新生成或购买；后续已通过 MiniMax 生成旧半身动作预览，但尚无批准方案的正式视频。

可用候选为 `kling-3-omni` 的 `element2video`：接受 1–7 张图片 `visualReferences`，可设 `duration=5`、`aspectRatio=9:16`、`generateSound=false`、`multiShot=false`、`resolution=pro`。三个图片参考的实时报价为 175 积分；表单未给 `pro` 的像素尺寸，不能写成已验证的 1080p。图片参考不提供精确首末帧锁定，角色一致性须检查实际生成结果，生成前仍须重新报价。

参考输入优先级为原 `MiaPortrait`（身份、画风和所有服装细节）、原创粒子图（开场质感）、首页构图（结束方向）。动作仍按已确认分镜，下一次提示要明确：

1. 保留原卷曲短发层次、大型黑框双晶体发饰、紫瞳比例、肩带与袖口结构、腰扣/链饰及单侧鱼网袜；不简化服装或改画风。
2. 从人物下沿先起，按裙腰、肩臂、脸发重叠凝形；永久星雾遮住下沿，不先出现孤立头部。身体凝形后头、肩与胸部共同转向镜头；相机和人物尺度固定，不能把镜头退远当成旋身。
3. 画面右侧、最终摆 V 的手在脸旁划一次小弧，光迹紧随指尖，再收为 V；另一手向观众伸出。光弧完成后再向下方无图标流光球流动，不提前绕头或横扫身体。
4. 生成只提供真实动态动作。末帧与原生首页的角色位置、尺度、下沿雾、流光球和控件必须另行合成并验收，不承诺靠参考图或短淡出自动对齐。

此前城市版按 9:16 整片铺满的估算显示：在 16 Pro 的 402×874 点屏幕上，视频约为 491.6×874 点，左右各裁 44.8 点；SE 的 375×667 点屏幕几乎不裁。当时首页角色与固定 84 点麦克风布局不与视频自动匹配。这是旧布局的风险记录，不是新版星雾首页的精确测量。当前末帧为 941×1672，仍需取得合格动态素材，按两种实际布局验收角色、下沿雾与无图标流光球收束；尚未取得正式素材或验证新动画衔接。
