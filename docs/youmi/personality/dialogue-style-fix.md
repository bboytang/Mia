# 内部标签泄漏与称谓重复修正

用户反馈回复夹带“悠米的回复”“陪伴者的历史回复，仅表示她说过的话”，且几乎每次都称呼“哥哥”。

原因是后端将来源说明直接加进历史 assistant 正文，模型可能模仿这些标题；为固定身份而重复的称呼映射、第一人称示例和情绪里的整份性格副本，又在同一请求中反复强调亲昵称谓。温暖状态的指导还主动要求使用称呼。

修正源码 `b51be7e770161fe759a192a2996031ebba5e54dc`：

- 当前启用性格的历史直接使用原生 assistant 角色，来源约束放在系统规则；旧历史中已泄漏的已知标题只在构建上下文时清理，不改数据库中的原对话。
- 输出守卫在语音、字幕和后续历史路径清理已知标题前缀；保留正文中的正常引用。覆盖流式分片拼接、只有标题的空片段和正文继续输出。
- 模型请求只保留一处称谓数据，情绪数值仍按完整原性格计算，但不再把整份性格重复放入模型可见的情绪 JSON。身份字段没有改写后台配置。
- 日常默认直接接话，呼唤、撒娇或确有必要时才使用称谓。最近两条回复已使用过称谓时，进一步提示普通接话不再重复；明确询问称呼时仍可回答。
