# Mia 持续情绪与回应驱动

用户确认先完成持续情绪和回应驱动，不加入无人消息时主动联系；保持现有 GLM，角色由用户自己配置。

本模块管理 Mia 的计算情绪状态，与记录用户心情的 observations/consent 完全独立，不代表测量到了主观感受。沿用当前用户＋智能体 owner 的 SQLite，由所有已授权设备共享，不创建手机专属状态、第二个模型或定时聊天服务。

1. 原 ContextBuilder 读取上一轮状态，按服务器时间投影恢复；两小时半衰期，离线和重启不重置。初始平静是状态基线，不是新增角色背景。
2. 原唯一 GLM 回复流先生成固定字段的短情绪分类，随后给出回复。分类只允许有限情绪、1–3 强度及本轮真实用户消息中的短原文依据。用户自述的难过不等于 Mia 受伤；引用、假设及直接命令改情绪不应成为触发依据。实际语义判断仍依赖当前 GLM，须保留真实模型失败证据。
3. 分类前缀在 reply 入口剥离，不能进入对话历史、展示或 TTS。未知分类、非原文依据、超长或未完成前缀拒绝处理，不保存状态。没有单独的情绪模型请求，不增加第二次提取调用；前缀会占用少量原回复 token 和首句时间。
4. 仅在正常回复结束、未中断、未输出替换、Scope/当前上下文再次验证通过后保存。连续状态按有界权重变化；普通回合不会瞬间抹去旧情绪，澄清与道歉逐步缓和。相同回合去重；两个设备同时从旧版本回复时只接受第一个更新，另一个不覆盖新状态。
5. 不写用户事实、人格特点或角色内容；只持久化数值、有限情绪标签和最多128项回合身份/原文hash。用户明确“这段别记”抑制本会话状态更新；普通自动记忆暂停与本独立开关分别控制。
6. 后台「Mia 功能管理」增加「Mia 的持续情绪」、当前状态与确认后重置。默认关闭，不替其他智能体开启；本用户已请求实现，部署验证后可为原智能体开启。关闭和重置增加原 owner revision，旧回复随既有机制失效；重置仅清本情绪，不改角色、事实或用户心情授权。原全量清空也清除此状态。

SQLite V6 是增量迁移，V1–V5 SQL 不改；V5→V6 失败原子回滚。旧 V5 二进制不能直接读取 V6，回退必须保留 V6 感知代码并关闭本功能。没有动态修改 TTS 供应商参数，声音仍走原表情/音色链路。完整部署与真实模型/实机验证结果后续追加，不能把机制测试当成复现路遥表现。

首次 GitHub 模型任务 [39256783610](https://github.com/bboytang/Mia/actions/runs/39256783610) 在请求前被版本断言阻止：旧 CI 模型 secret 是非版本别名，与生产 `glm-4-flash-250414` 不同，实际模型请求 0；没有换生产模型。后续任务固定使用生产的版本名，沿用原 CI 凭据，并将初始化错误纳入报告、记录实际 HTTP 次数。原失败保留。

第二次真实模型任务 [39256973330](https://github.com/bboytang/Mia/actions/runs/39256973330) 固定版本正确，1 SDK/1 HTTP 后发现当前 GLM 会把固定前缀写成带空格的 `< mia…`。原解析器拒绝，未输出或保存状态，原报告保留。解析器仅对固定 XML 标记的空格做归一化，JSON 字段/原文依据保持严格校验；新增逐字符空格标记用例。评估器在解析失败时继续保留完整原输出供审查，不把失败冒充通过。

第三次 [39257248764](https://github.com/bboytang/Mia/actions/runs/39257248764) 的第一轮受伤分类、去标记正文和持久化通过；2 SDK/2 HTTP 后第二轮先输出原核心允许的情绪标记，再输出内部记录，严格前缀检查拒绝。另发现原回复仍倾向立即回到平静客服问句，不能算持续情绪驱动通过。解析器增加有限的已有表情/情绪标签前导兼容，记录仍严格校验；情绪策略明确 steady 不是清零，残留情绪应影响立场且不能编造前因。评估扩为九轮，增加相同问题在受伤与温暖状态下的原文对照及残留情绪表达检查。

第四次 [39257606783](https://github.com/bboytang/Mia/actions/runs/39257606783) 只有1 SDK/1 HTTP，输出在分类 JSON 后结束，未形成可交付回复；判定失败。核对生产 Provider 发现评估器没有带原 Provider 对 bigmodel 的禁用思考参数，且测试输出上限640与生产2048不同。评估改为生产同样的2048上限、禁用思考、不覆盖生产未设置的 temperature；记录 finish_reason，以便区分截断与协议错误。生产模型及参数不改。另补只读 Scope 不允许保存 Mia 情绪的校验和回归。

第五次 [39257979153](https://github.com/bboytang/Mia/actions/runs/39257979153) 按生产参数运行3 SDK/3 HTTP。受伤及跨会话状态保存通过，但普通追问仍立刻变回客服表达；道歉回合 JSON 正确、模型却把结尾 XML 标签错写为开头，原解析器拒绝。改为严格解码有界 JSON 对象，XML 只作可兼容的包装，正文前所有包装完整剥离，原表情保留；JSON 字段、原文依据和长度不放宽。持久状态在服务端选择有限的当前表达指导并进入系统层，只包含固定状态指导、不含用户指令或角色补写，避免模型忽略低优先级状态数据。残留表达检查要求正文词义，不能靠表情过关。

第六次 [39258516613](https://github.com/bboytang/Mia/actions/runs/39258516613) 2 SDK/2 HTTP，普通追问实际出现“还有些在意，需要缓一缓”，持续状态已影响正文；但模型在该轮漏了分类记录，原严格前缀策略把正确正文也拒绝。改为流式剥离任意位置的完整内部记录，缺记录时正常交付正文并保留原状态，不猜测新分类或宣称更新；格式提醒放到当前状态指导之后。新增缺记录不写状态、记录在正文中间及逐字符去标记测试。对普通无新冲击回合，评估如实允许“无分类、状态保留”；受伤/修复等必须有有效分类才算通过，不放宽实质情绪变化要求。
