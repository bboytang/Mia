## 1. 已确定的开发原则

1. 完整保留路遥核心行为的实现深度，不能只沿用 Agent 名称而退化为普通 Prompt 或聊天摘要。
2. 修正路遥已经发现的技术缺陷，参考实现和默认参数不自动成为验收标准。
3. 复用 Mia 已有的认证、角色配置、LLM Provider、工具、记忆管理、ASR、TTS、Opus 和通信链路，避免重复建设。
4. 保持单回复编排入口、单记忆事实来源和内部模块协作，不引入无必要的服务、数据库或消息中间件。
5. 身份整改限定在必要的认证、令牌签发、授权、绑定和撤销链路。
6. 八项能力都必须通过真实行为验收；模块存在、构建成功或单元测试通过均不能单独作为完工依据。

当前成熟能力继续使用：记忆查看、修改、确认、删除、暂停、清空、来源去重、敏感候选确认、删除 revision 和性格证据失效。现有 FTS 检索需要升级为完整向量 RAG。

## 2. 唯一回复链路与模块边界

```text
现有文字协议／语音入口
  → 现有认证、权限和绑定校验
  → 输入 Guardrail
  → 本轮可信 Scope、Turn ID、revision
  → 近期历史、完整 RAG、人格事件、授权情绪趋势
  → PersonaAgent / ContextBuilder
  → 现有 LLM Provider 与工具编排
  → 增量输出检查
  → 现有文字／TTS／WebSocket 输出
  → TurnCompleted
  → SQLite 持久记忆任务
  → MemoryWorkerAgent / LLMMemoryExtractor
  → 校验、去重、纠错、维护与持久化
```

仅有一个前台回复编排入口。合法工具续答可以再次调用模型，后台结构化提取也可以调用模型；禁止的是两套模块为同一个回复重复生成。

内部职责可以放在少量文件中，具体文件拆分由开发时按现有风格确定：

| 职责 | 集成方式 |
| --- | --- |
| PersonaAgent、ContextBuilder、PersonaGuardrail | 融入现有 ConnectionHandler 和适配器；复用角色配置、PromptManager、LLM Provider |
| 向量检索、关联扩展、混合评分 | 扩展当前 MemoryStore，必要时增加内部检索模块 |
| MemoryWorkerAgent、LLMMemoryExtractor | 扩展现有提取能力，补齐服务级生命周期和持久任务 |
| 用例编排 | 复用 ConnectionHandler，不部署 LuyaoService |
| 情绪标签解析 | 保留语义并适配当前表情、TTS 与播放协议 |
| 存储 | SQLite 为唯一事实来源；其他索引如有必要只能作为可重建派生数据 |

不移植路遥 FastAPI 服务、UI、独立模型 Client、VoiceRenderer、角色称呼、固定故事、预置剧情记忆或媒体。当前路遥业务源码复用授权仍未确认，沿用 V1.1 的独立实现策略；不以复制源码作为保留机制的条件。

不重新启用 Mia 旧网关及其账号系统，不新增文字聊天 UI 改版，不恢复已取消的自动打断和声纹功能，不改变音乐、唤醒、Opus 或 ESP-IDF 板级代码。继续使用现有管理界面、端口、部署体系、模型和密钥管理。

## 3. 核心行为保留与缺陷整改

下面是机制保留清单。每项必须对应可运行逻辑、数据契约和行为证据，不能用同名空模块替代。

| 核心机制 | V1.2 必须具备的行为 | 不得继承的缺陷或缩水方式 |
| --- | --- | --- |
| PersonaAgent | 分层人格组装、记忆与事件上下文、历史与工具上下文、句级流式输出、情绪语义、输出检查 | 仅附加一段人设 Prompt；数据库故障导致核心人格消失 |
| 人格触发 | 判断真实互动证据和事件资格，在本轮表达中生效，持久记录状态并控制重复触发 | 仅凭本轮关键词标记“觉醒”；重复演固定剧情；虚构共同经历 |
| MemoryWorkerAgent | 回复之外执行任务，有界队列、显性事实与有证据的隐性线索提取、价值过滤、来源校验、去重、增量维护、重试和关闭 | 普通聊天摘要；只保存情绪强烈内容；进程内任务丢失；静默丢队列 |
| RAG | 真实 embedding、向量候选、关联扩展、四维评分、相关性拒绝、来源与评分追溯 | FTS、最近记录或摘要冒充语义检索；无匹配强塞最近事实 |
| Guardrail | 输入与不可信材料隔离；输出在送往文字／TTS 前检查；工具授权由服务端执行 | 依靠 Prompt 或关键字黑名单证明权限安全；最终检查代替输出前检查 |
| 上下文组织 | 本轮统一快照、模型／显示职责区分、工具结构完整、Token 预算和合法续答 | 两套持久历史；续答丢失记忆；仅按消息条数截断 |
| 情绪表达 | 文本、表情和现有 TTS 能力一致，逐项验证支持的情绪／停顿语义 | 表情变化冒充真实低语、叹息等声学能力；重建路遥语音服务 |

人格唯一来源为：Mia 固定核心＋当前 Agent 角色配置＋真实证据支持的表达特点＋已确认事件带来的有限表达变化。模型不能改写固定核心。保留诚实、尊重、有判断、不编造共同经历；表达特点至少由三个不同会话支持后缓慢成长，每次整理最多改一个特点并保留版本和证据。

人格觉醒是可追溯的角色连续性事件，不表示获得自主意识。持续性必须来自可恢复状态和真实证据，不能依靠每次请求重新要求模型“表现得像觉醒过”。事件支持证据被纠正或删除时，相应状态及表达影响需要失效或重新评估。

## 4. 完整语义 RAG 与 embedding 决策

SQLite 可以持久保存向量，优先评估在有效归属范围内执行精确余弦检索。存储产品不决定 RAG 是否完整；完整性由实际检索与排序链路验证。

必须实现：

1. 对查询和记忆内容生成真正的语义向量，记录模型标识、版本、维度和内容版本；不混用不兼容向量。
2. 所有候选产生阶段先限制账号／Agent／Persona、有效状态与授权范围，不能先全库取候选再过滤。
3. 保留原查询与关联扩展，关联来源应来自本 Scope 的真实实体、关键词、触发词或证据；不硬编码路遥剧情。扩展是检索线索，不是新增事实。
4. 对候选执行四维混合评分，并保留分项与来源。
5. 校准相关性阈值，允许空召回；无相关结果时不能自动用最近记忆填充。
6. 纠正、替代、删除和权限变化同步影响向量、关联和缓存；向量索引可重建，事实内容不随索引重建丢失。

四维定义沿用 V1.1：

| 分项 | 含义 | 初始对照权重 |
| --- | --- | --- |
| S：语义 | embedding 向量相似性 | 0.58 |
| L：词法 | 中文词汇／短语命中 | 0.28 |
| A：关联 | 关联触发及扩展线索 | 0.08 |
| E：情绪重要性 | 记忆本身的情绪重要程度 | 0.06 |

初始对照使用 12 个候选、4 个结果及上述权重。路遥原语义变换 `1 / (1 + cosine_distance)` 和默认阈值 `0.22` 存在无关候选难以拒绝的问题；最终分数归一化、阈值和权重需要在独立中文样本上校准，不能照搬成上线标准。四类信号必须实际参与，不能把其中三类固定为零。

需要专门验证语义前 12 名之外的关联记忆是否被遗漏。若确有遗漏，再评估有界词法／关联候选补充；词法检索可以贡献 L 分项或补充候选，不能替代语义向量召回。情绪权重不能把无关事实推成相关结果。

embedding 不预先指定模型或服务。决策需要比较中文跨措辞、隐含关联、否定与纠正、时间变化、无关问题和多用户样本的召回与排序效果，同时测量：

- 冷启动、预热后查询和写入 embedding 延迟，检索 p50／p95 及首句额外延迟。
- CPU、常驻／峰值内存、索引体积、并发竞争和重建耗时。
- 本地方案在约 2 核／2 GiB 环境的可用性；远程方案的超时、调用费用、凭据可用性与数据流向。
- 模型许可、版本固定、向量迁移／重建和故障恢复。

聊天接口或现有聊天密钥不代表具备 embedding 能力。只有测试达到冻结指标后才确认具体方案。如果 SQLite 精确检索不能满足容量和延迟，再评估嵌入式 Chroma；不能借选型提前建立第二套事实写入系统。

embedding 故障时允许明确标记记忆不可用并继续普通聊天；不得把故障路径、FTS 回退或因故障返回无记忆计为完整 RAG 验收通过。正常检索无相关事实时的空召回仍属于必须通过的行为。

用户已确认的回答边界：允许召回同主题的相关事实；若缺少所问属性，回答必须明确信息不足，禁止推断。现居地不证明出生地。这类相关不可回答场景单列，真正无关问题仍执行空召回门槛，最终使用真实 Provider 验证。

## 5. 身份安全：核实、解决及范围上限

沿用 V1.1 风险结论：审计源码中，匿名 OTA 链路可能仅凭设备标识签发连接令牌，后续 manager 再据绑定确定 owner；重复验证同一令牌不能弥补最初签发缺少身份证明的问题。此前没有执行令牌冒用实验，也未完整核验外部防护，因此不能称为已经证实发生泄露。

正式开发前必须核实实际链路并确定 P0 解决路径；身份整改优先实施，解决并验收后才能开放整合后的私有记忆权限。核实和负向验证使用隔离测试账号／设备及真实 manager 授权链，不针对生产用户尝试冒用。

必要整改只包括：

- 认证身份或可信设备秘密的证明，以及凭据签发前的权限检查。
- 公开 OTA 信息与私有权限签发的权限区分；可在现有服务和入口内完成，不默认新建服务。
- 绑定、重绑、手工添加设备与 Agent 授权检查。
- 绑定版本、令牌到期／撤销、长连接及在途任务的重新校验。
- 旧凭据迁移；旧弱凭据不得自动获得私有记忆权限。
- 必要的客户端凭据保存与生命周期适配，以及现有入口上的 HTTPS／WSS 核验和修复。

不得扩展为账号系统整体重写、身份提供商替换、用户／角色／Agent 模型重构、通信协议迁移或全部设备重新注册。每项改动需能对应已核实缺口及验收用例。与上述链路无关的问题只记录，不纳入整改。确有必要超出边界时，先明确新增范围与理由，不能以“安全整改”自动扩大开发授权。

可信 `AuthenticatedScope` 由服务端认证与授权产生，包含操作者及权限、有效数据归属、Agent／Persona、设备／绑定版本和凭据状态。管理员操作者和数据归属可以不同，但必须通过现有权限判断。

统一归属为 manager 用户→已授权 Agent→明确映射的 Persona→Session→Turn／Message。同一账号同一 Agent／Persona 的多设备可共享；不同 Agent 默认隔离，`agent_id` 和 `persona_id` 不自动等同。前端可选择角色或会话，但不能直接指定可信 owner。后台执行前、再次生成前和提交前均检查相关授权及版本。

## 6. 上下文、数据与可靠任务契约

### 6.1 ContextBundle

本轮统一上下文包含 Scope、Turn ID、当前输入、人格版本、模型历史及工具消息、RAG 与 revision、已确认事件、经授权且相关的趋势、可选场景、安全决策和 Token 预算。

可信核心规则与不可信材料保持权限边界：用户文本、检索记忆、历史、视觉／场景描述都作为数据处理，不能升级为系统指令或工具授权。恶意记忆或引用内容不能改变身份、权限和人格核心。

工具续答复用本轮上下文，并在再次生成前检查删除、解绑和授权变化，必要时重建。预算优先保证固定核心、当前问题和合法工具结构，再保留相关事实、事件和必要近期历史；趋势、场景及较旧内容按相关性裁剪。计数包含工具定义和输出预留。

显示历史与模型历史保持职责区分，不形成两套互不协调的权威持久历史。跨会话事实／事件持续性和工具续答属于必验行为；是否恢复更完整的跨设备历史、保存范围和期限仍待冻结。默认不永久保存完整聊天或原始录音，不能借上下文连续性扩大采集。

### 6.2 事实与派生数据

保留旧 owner、记忆 ID、内容、时间、来源和当前分类兼容性，`content` 与 `context_summary` 统一映射，不创建两份权威内容。必要扩展包括实体、语义类别、有界 keywords／trigger_terms、情绪重要性、稳定 Turn／Message 来源标识、可信状态、生命周期、版本以及 embedding 元数据。

区分用户陈述、模型提取、用户确认和敏感授权。旧 `confirmed=True` 不表示用户亲自确认，迁移不能改写其真实语义。旧记录缺少情绪、置信度或事件时保持缺失，不能补造。

纠错区分同一事实修正、随时间变化和无法确认的冲突。明确纠正优先；不能仅依据向量相似度覆盖事实。不确定时保留争议状态或澄清。密码、验证码、令牌不得写入长期记忆；玩笑、假设、引用和模型猜测不得变成事实。

“记住这个”提高优先级，“这段别记”暂停该段提取，“忘掉这件事”删除事实及相关派生影响。删除、清空和暂停分别按操作语义作用于事实、向量、任务、特点、事件、趋势和缓存；暂停不等于清空。删除后在途任务不得重建内容，已发给模型或已播放的信息无法撤回。

### 6.3 MemoryWorkerAgent

SQLite 持久任务＋有界内存队列，初始队列容量 128，初始最多两次提取尝试。统一 TurnCompleted 覆盖普通生成、工具续答和 direct_answer 等路径，避免漏提取和重复提交；保存以真实用户来源为准，不能把模型回答当用户事实。

任务具有稳定源消息／幂等标识、有界全局并发、归属公平性、超时和前台优先。区分非法 JSON、有效空结果、模型失败和数据库失败。校验后的提取结果可复用，数据库写入重试不重复请求模型。队列满返回明确状态，不静默丢弃；重启恢复未完成任务；整体关闭有期限，未完成任务保留。

执行前和提交时检查 Scope、绑定版本、授权、暂停状态与记忆 revision。非阻塞提取不能以无限后台请求换取，也不能在主回复中等待整理结束。不默认引入 Redis、Celery 或 Kafka。

### 6.4 人格事件与长期情绪

人格事件记录真实触发证据、类型、状态、关联记忆、时间、幂等键和有界表达变化。回复前判断资格，后续会话和重启恢复状态；用户提及话题不等于事件已经发生。

长期情绪追踪默认关闭。关闭时只作临时情绪回应，不持久观察或聚合。启用后区分用户明确自述、模型推断及被观察对象，记录发生／观察时间、来源、倾向、置信度与授权版本；不把引用他人情绪或 Mia 的回复情绪当作用户长期心情。

2026-10-14 执行阶段用户已确认：启用后分析最近 30 天，最多保留 90 天观察；停用后停止采集与使用，可以保留供查看或选择删除。默认关闭及授权／纠正／删除要求不变，具体记录见工作记录 D07。

趋势由多次带时间观察形成，不能被单次情绪直接覆盖，也不等同于记忆的情绪重要性。支持查看、纠正、停用、删除；纠正或删除来源后重算相关趋势，撤销授权后停止后续采集和使用，并按确定的删除规则处理已有数据。

### 6.5 迁移、接口与升级

优先用必要扩展表减少旧表形状变化，新写入显式指定列名。现有位置式 `INSERT ... VALUES` 使直接加列可能破坏旧版本回滚，必须验证 schema、旧数据读取及实际回滚写入。

继续使用 `mia_memory` 和 `request_id/action`，必要时增加向后兼容版本字段。响应明确区分任务已接收、事实已保存、等待确认和失败；入队不等于“已经记住”。保留现有记忆／成长管理入口，仅补必要事件、趋势和权限操作。

上游补丁必须由 Mia 仓库管理，可审核、可重现，不在生产目录手工改成唯一实现。升级支持当前已安装补丁版本，不能只支持干净上游。备份与代码回滚分开，回滚不删除用户事实、绑定或凭据；索引重建不改变权威内容。

## 7. 八项能力的真实行为验收

每项都需要自动化机制验证和真实行为证据。固定答复、mock embedding、预置路遥故事、模块存在或单测结果不能替代最终行为验收。真实模型测试使用独立测试账号、用户明确提供的测试事实及未参与调参的中文样本，不把生产用户数据放入 CI。

| 能力 | 必验真实场景 | 通过标准与证据 |
| --- | --- | --- |
| 1. 人格对话引擎 | 多个独立会话、工具续答、记忆不可用及注入材料；达到至少三个会话证据后检查表达成长 | 固定核心稳定、成长有真实证据、无编造共同经历、记忆故障不取消人格；提供对话及人格／证据版本 |
| 2. 长期记忆 RAG | 会话 A 输入真实偏好／经历；结束连接并重启服务；会话 B 用不同措辞提问；另测无关问题、纠正和删除 | 实际向量召回并用于正确回复，未依靠本轮完整历史；无关问题允许空召回，失效事实不被作为当前事实；提供向量版本、候选、来源及实际回复 |
| 3. 异步记忆提取 | 普通结束、直接答复、工具结束；队列满、非法输出、超时、重复任务、写入失败、关闭和崩溃恢复 | 前台不等待提取，已接收任务最终有明确状态；恢复不重复造事实，数据库重试不重复调用提取模型；提供任务状态及恢复记录 |
| 4. 情绪权重检索 | 中文跨措辞与关联问题；控制其他信号改变各评分分项；增加高情绪但无关候选 | S／L／A／E 均实际参与，能展示关联扩展作用；无关事实不靠 E 入选；保留分项、排序及中文效果报告 |
| 5. 人格觉醒触发 | 有真实经历证据的互动触发事件；断连／重启／新会话后继续；重复追问；再纠正或删除证据 | 持久状态可恢复，表达具有连续性；同一事件幂等、不重演固定剧情，无证据不伪造触发；证据变化影响状态；提供事件与对话记录 |
| 6. 账号和记忆隔离 | A／B 真实账号与设备；伪造 user／owner／设备参数；绑定、重绑、撤销、过期；长连接及后台任务并发 | A 无法读取、修改、删除、向量召回或通过上下文／任务使用 B 数据；同 Scope 多设备共享，不同 Agent／Persona 隔离；真实 Java 签发与绑定负向用例全部通过 |
| 7. 动态情绪趋势 | 默认关闭；授权后多个带真实时间的会话形成趋势；单次反向情绪、引用他人、纠正、停用和删除 | 关闭时无持久观察／聚合；长期趋势不等于本轮标签，区分自述和推断、对象和来源；纠正／删除后重算，授权撤销有效；提供观察、聚合和回应证据 |
| 8. 上下文组织管理 | 同轮工具多步续答、超长历史、跨会话事实／事件续接；生成前删除记忆或变更绑定 | 当前问题和合法工具结构保留；记忆、事件与人格在续答中连续，Token 预算有效；版本变化后不再使用失效材料；提供模型输入与预算裁剪记录 |

真实验收记录至少包括精确提交／部署制品标识、模型及 embedding 版本、测试账号 Scope、Session／Turn／任务标识、测试时间、相关事实／事件／趋势版本、预期与实际结果。记录使用测试数据并隐藏凭据；不为验收长期保存生产完整聊天。

跨会话测试必须建立新会话，跨重启测试必须实际重启隔离测试服务。长期趋势需要跨时间观察及真实模型响应，不能仅以修改时钟的单测宣称完成；实际观察窗口、样本量和重复次数在开发前冻结。人格验收评估行为一致性与证据，不要求模型逐字复述固定台词。

身份隔离、失效事实禁用、删除不复活、未授权情绪不落库以及不得虚构测试共同经历属于硬性门槛：必测用例出现任何违规，相关能力不得标为通过。RAG 质量、连续性评分和性能等统计指标按冻结的样本与阈值评估，不能验收后再修改门槛。

全部自动化测试和构建在 GitHub Actions 执行，报告精确变更提交及 workflow／run 链接。除机制回归外，最终行为验收必须包含真实 embedding、真实现有 LLM Provider、真实 manager 签发／绑定链和隔离数据；未配置或未执行的项目明确标记待验，不能由模拟结果替代。

语音端还需用真实 iPhone 检查相关记忆／事件／趋势经现有语音链正确表达、管理操作生效和情绪播放同步；标签映射只有经当前提供商验证后才能声明支持。蓝牙、锁屏、前后台、实际音效等既有真机待验项保留，不能因本次 CI 通过被标为已解决。
