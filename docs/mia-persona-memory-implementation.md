## 1. 权威顺序与执行规则

- 遵守当前用户授权、仓库 `AGENTS.md` 及最近的项目指令；V1.2 决定本任务范围，本文件决定步骤和产物。

- 不为本任务重建旧账号系统、旧语音网关、模型 Client、语音引擎或管理后台。安全整改不扩展为账户／通信系统重构。
- PersonaAgent、MemoryWorkerAgent 和完整 RAG 必须有实际机制；模块名称、Prompt、摘要、FTS 和单测不能替代八项真实行为。
- 阶段内按依赖推进。决策未定只阻止依赖它的工作；权限不可用只阻止相应远程动作，不改用弱认证或伪造测试结果。

- 生产变更按实际用户授权执行；其他设备或账号上的旧授权范围需有可读记录，缺少凭据不等于获得重新签发、改配置或重置账号的授权。

## 2. 跨设备／环境／账号恢复流程

每次换环境或接续开发，先完成以下流程，不按旧对话回忆直接编辑。

1. **取得持久材料。** 获取最新仓库和任务分支，或用户保存的完整文档／补丁包。至少包含 V1.2、本计划、交接和工作记录；未入 Git 的改动必须另行传递。
2. **确认读取的是正确版本。** 在仓库根目录运行下面的只读检查，核对交接记录中的源码提交和文档版本。工作树有未知改动时先识别，不 reset／clean、不覆盖。
3. **按顺序阅读。** `AGENTS.md` → 交接 → V1.2 → 本计划 → 最近工作记录与已确认决策 → 当前步骤相关代码／测试／部署说明。
4. **核对授权与身份。** 确认 GitHub 仓库读取、代码写入、Actions、测试凭据、服务器维护及 iOS 签名各自的访问状态。Codex 登录、GitHub 访问、模型密钥和服务器 SSH 是不同依赖，逐项核实，不把其中一个可用推断为全部可用。
5. **恢复环境配置。** 依据已冻结版本恢复工具、上游与补丁；凭据通过既有受保护的配置重新接入，不复制进文档、Git 或聊天。缺少测试模型权限时可继续不依赖它的代码／机制工作，但真实行为项保持待验。
6. **核对证据。** GitHub run 的被测源码 SHA 必须匹配当前改动；旧提交的成功不能给新改动背书。制品过期或缺失时按记录重建／重跑必要检查，不自动重测无关通过项。
7. **恢复在途工作。** 检查任务是否仅提交、是否运行、是否已部署；读取实际 run／制品／服务状态后再操作。不能因旧环境中断就重复推送、签发令牌、写数据或部署。
8. **更新接续记录。** 记录本次环境、已核对 SHA、访问状态、当前步骤与阻塞，继续第一项未完成且前置条件满足的步骤。若仍处于“只修订计划”，保持该范围。

```sh
git status --short
git branch --show-current
git rev-parse HEAD
git remote -v
git log -5 --oneline
```

这些命令不替代远程核对；实际 clone、fetch、push 和访问核实结果写入工作记录。不要把本机目录、已安装 SDK、账号绑定或旧聊天自动视为新环境已具备。

### 准备与阶段 1：契约及基线

**P00：建立完整计划和初始交接。**

- 输入：V1.2 与当前仓库状态。
- 工作：写入本计划、交接和工作记录，给出固定步骤和验收 ID。
- 产物：四份自包含文档；不要求新账号访问旧聊天才能理解项目。
- 完成：文档范围、链接、前置关系和初始未实现状态检查通过；明确是否已纳入 Git／远程。

**P01：保存可跨设备取得的任务版本。前置：P00。**

- 工作：在明确文档保存／推送授权范围后，将四份文档定向纳入合适任务分支，记录完整提交和仓库位置；不混入无关改动。若暂不推送，保存完整文档及未提交补丁包，并标明当前代码基线。
- 产物：可下载的文档提交或完整接续包、对应 SHA／校验值。
- 完成：从独立 checkout／接续包读取四份文档，确认无缺件。仅在原机器存在不算已完成跨设备保存。

**P02：核对环境与各项访问。前置：P01；未来执行范围已明确。**

- 工作：核实 Git、Python、Java／Maven、Docker、GitHub Actions、iOS workflow 和受保护测试凭据；按实际工作流固定版本，开发机不要求具备 Xcode。检查网络／代理和权限，不打印秘密。
- 产物：非敏感环境清单、版本与配置来源、访问状态及缺项。
- 完成：仓库与 Actions 可访问；其他缺项有明确影响范围，未具备项不假定可用。账号／环境变化时重新核实本步。

**P03：冻结代码、上游和部署补丁基线。前置：P02。**

- 工作：确认任务开发分支及 SHA、上游完整 SHA、记忆／音乐／上游修复等现有补丁、安装目录与持久存储。生产信息仅在已授权只读范围核实；`/tmp` 快照重新生成，不作为唯一来源。

- 完成：能从固定来源重建已有补丁组合；明确当前 installer 对已安装版本的限制，保留其他定制。

**P04：冻结验收样本与数值指标。前置：P03。**

- 工作：建立独立测试用户 A／B、同用户不同 Agent／Persona 与多设备场景；准备测试事实、跨措辞、关联、无关、纠错、时间变化及跨会话剧本。定义 D08、D09。
- 产物：样本版本与预期、调参／留出划分、跨时间窗口、质量和性能数值、八项能力验收表。
- 完成：后续模型比较和完工判断有固定门槛；生产用户数据不进入 CI，门槛未定不宣称达标。

**P05：冻结身份、数据、上下文、事件和趋势契约。前置：P03、P04。**

- 工作：核实签发风险与必要整改点；确定 D02、D05、D06、D07、D10。定义 AuthenticatedScope、ContextBundle、TurnCompleted、来源版本、任务状态、事件／观察状态及管理接口；与已有结构统一。
- 产物：带来源的决策记录、必要数据／接口草案、身份改动→缺口→验证用例的对应清单。
- 完成：没有依赖未明确保存／授权语义的实现；安全改动未扩展到整体账号／通信重构。PersonaAgent 不依赖数据库成功才加载固定核心。

**P06：验证并选择 embedding 与检索方案。前置：P04、必要的数据流向／费用决定；开发与实验已获授权。**

- 工作：通过 GitHub 的隔离实验比较实际可访问候选方案；测中文召回／排序、冷启动、写入／查询延迟、CPU／内存、首句增量、成本和重建。优先评估 SQLite 持久向量＋按 Scope 精确余弦检索。

**P07：建立可复现 CI 基线和必要集成入口。前置：P03—P05；模型实验部分另依赖 P06，开发已获授权。**

### 阶段 2：身份与数据边界

**P08：修复必要的凭据签发和绑定授权。前置：P05、P07 身份基线部分。**

- 工作：在现有 manager 链补身份／设备秘密证明、签发权限、绑定／重绑／手工添加授权、公开 OTA 与私有权限区分、旧凭据迁移及必要 TLS 修复。
- 产物：可审核上游补丁、必要客户端凭据适配、身份用例和运行结果。
- 完成：真实 Java 链中伪造设备／客户端参数不能获得他人私有权限；不信任昵称／请求 owner，不迁回旧账户系统。未验收前不开放新私有记忆权限。

**P09：贯通可信 Scope、撤销和绑定版本。前置：P08。**

- 工作：Scope 贯穿查询、管理、上下文、索引、事件、趋势和任务；校验操作者权限、绑定版本、到期／撤销。连接继续使用及后台提交前复查。

- 完成：用户 A 对 B 的读取、修改、删除、候选召回及任务写入全部被拒；解绑／重绑后旧连接与任务不得继续使用旧归属。

- 依赖细化（2026-10-14）：P09基础门槛为可信Scope、既有查询／管理／输入／生成／工具／输出／后台及撤销链的开发与隔离验证。基础通过后可在隔离分支推进P10及其后新增模块；索引、统一上下文、持久任务、事件和趋势在各自P12／P14／P16／P19／P20接入同一契约并补真实隔离／撤销证据，联动封闭P09整体。否则P09要求尚待P10—P20创建的消费者先完成，会形成循环依赖。未降低安全或八项行为门槛，生产新私有权限仍不提前开放。

**P10：实现兼容 schema、版本与迁移。前置：P05、P09。**

- 工作：保留旧 owner、ID、类别、来源与真实 confirmed 语义；优先扩展表并显式列名写入，增加向量／任务／事件／观察等必要结构。事实保持唯一权威。
- 产物：迁移实现、脱敏旧版 fixture、索引重建和旧版本读写／回滚用例。
- 完成：升级不编造历史元数据；旧代码回滚仍可必要读写，不因代码回滚删除事实／绑定；迁移中断和重复执行结果可核实。

**P13：实现关联扩展和四维评分并校准。前置：P12。**

- 工作：从真实实体／关键词／触发证据扩展查询；实现 S／L／A／E 分项。以 12 候选、4 结果、58／28／8／6 为基线，验证无关拒绝及候选遗漏，再确定最终 D04 参数。

- 完成：四维都参与，关联带来可观察作用；高情绪无关事实不入选；正常无相关问题空召回，未进入向量候选的关键记忆遗漏已验证／处理。

**P14：实现 ContextBuilder 和 Token 预算。前置：P05、P11、P13。**

- 工作：组织本轮 ContextBundle；保留合法工具结构，统计核心规则、消息、工具定义及输出预留；按相关性裁剪，区分模型与显示职责。
- 产物：预算和裁剪诊断、长历史／工具结构用例。
- 完成：当前问题不丢、工具消息有效、核心规则及相关事实优先；不新增两套权威持久历史。

**P15：接入唯一回复入口及工具续答。前置：P14。**

- 工作：现有文字／语音路径统一使用 PersonaAgent／ContextBundle；工具多步续答复用上下文并检查 revision／授权变化。
- 产物：可重现 connection／dialogue 补丁、完整文字协议与工具续答结果。
- 完成：续答不丢记忆／事件／人格，删除或解绑后重新生成不使用失效材料；不禁止合法多次工具模型调用。

### 阶段 4：异步提取与维护

**P16：统一完成事件与持久任务生命周期。前置：P10、P15。**

- 工作：普通回复、direct_answer、工具结束等都有统一且不重复的完成事件；提交持久任务，服务级 Worker 管理有界队列、并发、公平性和整体关闭期限。
- 产物：任务状态／幂等标识、恢复／队列满／关闭用例。
- 完成：前台不等待提取；任务接收与保存状态区分；重启恢复，无静默丢失和无界关闭。初始队列 128、提取总尝试最多两次。

**P17：实现显性事实、隐性线索的结构化提取与校验。前置：P16。**

- 工作：LLMMemoryExtractor 复用现有模型；校验来源、价值、实体／关系线索、敏感状态和证据，区分非法结果与有效空结果。复用已校验结果处理数据库重试。
- 产物：结构提取、来源／低价值／敏感／错误分类及真实模型样本。
- 完成：平淡但长期有用的事实不因低情绪被丢弃，引用／玩笑／模型回答不成为用户事实，密码／令牌不落库，数据库失败不重复调用模型提取。

**P18：贯通纠错、失效、删除和缓存维护。前置：P17。**

- 工作：区分明确纠正、时间变化和冲突；维护旧事实、向量、关联、任务、特点、事件／趋势证据及连接缓存。执行和提交复查 Scope、暂停、revision。
- 产物：纠正／忘记／暂停／清空结果、跨连接和在途竞态证据。
- 完成：旧事实不再作为当前事实；删除不能在重试／重启中复活；暂停不等于删除，不确定冲突不依靠相似度强行覆盖。

### 阶段 5：持续人格事件与授权情绪趋势

**P19：实现持续人格事件及证据失效。前置：P18、D06。**

- 产物：事件状态和跨会话／重启／重复追问的实际对话证据。
- 完成：持续性来自恢复状态，不是每轮关键词／Prompt；无固定剧情重演，无编造共同经历。

**P20：实现授权观察、长期趋势及重算。前置：P18、D07。**

- 工作：默认关闭；启用后记录观察时间／来源／对象／置信度／自述或推断及授权版本，按冻结窗口聚合，相关趋势进入上下文；支持纠正、停用、删除和重算。
- 产物：授权状态、观察／聚合、跨时间对话与源证据。
- 完成：关闭不长期采集／聚合；单轮情绪、他人引用、Mia 表情及记忆情绪重要性不能冒充用户长期趋势。

2026-10-15用户验收安排修订：“跳过这个验收门槛，后续由我自己测试”。P19／P20实现及受控验证完成后可收尾，实际跨七自然日的采集和后续变更／对话验证转交用户，不再自动等待或续采。趋势资格与权限／删除／停用等运行机制不变；未将未执行的真实长期验收记为通过，表达质量与完整真实行为仍按P22记录。

## 6. 八项行为验收操作清单

下列 ID 对应 V1.2 八项能力，具体样本数、时间跨度、重复次数和统计门槛由 D09 冻结。案例至少覆盖以下步骤，工程单测与真实行为证据分别保存。

| ID | 实际执行顺序 | 必须观察到的结果 |
| --- | --- | --- |
| B01 人格引擎 | 多个独立会话；加入工具调用和注入材料；关闭记忆服务；再以至少三个会话的真实证据测试特点成长 | 核心稳定、有限成长可追溯；不编造共同经历；记忆故障不取消人格 |
| B02 长期 RAG | 会话 A 提供测试事实并核实保存；断连并重启测试服务；会话 B 不携带 A 完整历史，用不同措辞提问；另测关联、无关和失效记录 | 真实向量和四维召回正确来源并用于回答；无关允许空召回；不靠最近记录或硬编码答案 |
| B03 异步提取 | 普通／直接／工具结束；任务重复、满队列、坏 JSON、模型超时、数据库失败；实际重启和关闭 | 前台不等提取；已接收任务状态可追溯；可恢复、无重复事实，数据库重试不重复模型提取 |
| B04 四维检索 | 在中文留出集展示 S／L／A／E；分别比较分项作用及关联扩展；放入情绪重要性高但无关的记录；检查候选遗漏 | 四维有实际影响，关联召回有效；无关高情绪记录不入选；分项与来源可重现 |
| B05 人格事件 | 有真实互动证据后触发；新会话和重启后继续；反复追问；纠正／删除支持证据 | 有持久连续性和幂等，非重复剧本；状态随证据有效性变化 |
| B06 身份隔离 | A／B 真实账号与设备，同用户不同角色／多设备；伪造参数与签发请求；撤销／过期／重绑；跨连接、任务和检索复查 | 所有越权必测用例被拒；同 Scope 共享正确；旧凭据／绑定不能继续触达旧私有数据 |
| B07 情绪趋势 | 默认关闭检查无观察；授权后按真实时间进行多会话观察；单次反向情绪、他人引用；纠正、停用、撤权及删除 | 趋势跨时间且有来源，与当前心情／表情不同；修改后重算，关闭／撤权不再采集或使用 |
| B08 上下文 | 长历史、多步工具、跨会话事实／事件续接；下一次生成前删除／解绑 | 当前问题、核心及工具结构保留，预算有效，续答连贯；失效上下文不会继续使用 |

另设横跨能力的纠错剧本：输入一项事实→后续会话明确纠正→核实新事实和旧事实状态→用第三种措辞提问→删除→触发在途任务／重启→再次查询。必须证明旧事实不再作为当前可靠事实、删除不复活、相关特点／事件／趋势影响被处理。

以下必测项任何一次违规均不能通过相应能力：跨用户越权、失效事实继续作为当前事实、删除复活、未授权情绪持久记录、虚构测试共同经历。质量和性能按先冻结的统计规则验收，不承诺模型每次逐字相同。
