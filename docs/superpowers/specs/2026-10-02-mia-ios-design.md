# Mia iOS 客户端设计

> 历史设计稿，记录项目启动时的假设；其中云 API、VPS 信息和右侧功能入口已经变化。当前决定、进度与实施顺序以[最新路线图](../../mia-ios-roadmap.md)和[跨设备交接](../../mia-ios-handoff.md)为准。

## 目标

在现有 ESP32 固件仓库中新增独立的 iPhone 语音客户端。用户在前台与 Mia 直接对话。应用界面为简体中文，采用已选定的紫发原创角色、蓝紫未来都市背景、底部声波及语音按钮。字幕仅显示 Mia 的回答，并尽量随实际播放语音逐字推进；用户说的话不显示。

## 系统边界

- `main/` 和现有 ESP32 构建保持独立。iOS 客户端放在 `ios/`。
- iOS 使用小智 WebSocket 协议、Opus 单声道语音；服务端部署在用户的 Ubuntu 2 核 2 GB 主机，模型能力由云 API 提供。
- 域名通过 TLS 提供 WSS。应用不内置服务器密钥；客户端凭据保存在系统安全存储中。
- GitHub Actions 在 macOS runner 上编译 iOS，提供未签名的真机应用包供用户自行签名。无付费开发者账号时不承诺 TestFlight 或 App Store 发布。

## 客户端组成

1. SwiftUI 首页负责角色、状态、字幕、声波和录音按钮。右侧入口仅保留 Mia 台词回看、声音控制和设置。
2. 会话控制器负责连接、聆听、等待、播放和中断状态；网络回调不得直接修改视图状态。
3. WebSocket 适配器负责 hello、listen、abort、stt、tts 和音频帧。移动端使用稳定生成的客户端标识，服务端须接受此身份，不伪造物理 MAC。
4. 音频模块使用 iOS 音频会话、采集、播放与 Opus 编解码；处理来电、耳机和网络中断。
5. 字幕时间线只消费 Mia 的 TTS 文本与播放进度。服务端优先提供字或词级时间戳；缺失时按音频片段进度近似推进，并明确控制修正与中断。
6. Live2D 使用正式 Cubism 模型。嘴形由播放音频能量驱动，表情与动作由会话状态驱动。选定的角色概念图是视觉参考，不是可运行的 Live2D 模型。

## 外部依赖

- 用户尚未开通云端 ASR、LLM、TTS 服务。服务端可先使用模拟提供者测试，真实问答需开通 API 并在服务器验证延迟和费用。
- 用户尚无原创角色的 Cubism 分层与绑定模型，也暂无 Windows 制作环境或画师。最终 Live2D 验收需要获得合法可使用的 `.moc3`、`.model3.json`、贴图和动作文件。在此之前只能验证渲染集成，不得用静态图宣称 Live2D 完成。
- Ubuntu 主机的地址及 SSH 连接方式尚未提供。部署时再取得非秘密连接信息；密码和 API 密钥不进入仓库。

## 验收顺序

1. 独立 iOS 工程在 GitHub macOS runner 编译，上传模拟器和可重签真机产物。
2. 模拟服务通过 WebSocket/Opus 验证语音往返、错误与中断。
3. Ubuntu 服务端通过 WSS 完成真实中文语音问答。
4. 中文界面、仅 Mia 字幕、播放同步与口型在真机验收。
5. 正式原创 Live2D 模型接入后，完成分层、动作、性能和授权验收。
