# P04 验收样本与冻结指标 v1

冻结日期：2026-10-14，D08／D09。以下是开发与实验的工程门槛，不是测量结果。实验后不得为了通过降低门槛；修改需记录理由、版本和受影响验收。

## 中文检索与样本

`server/tests/fixtures/persona_memory_retrieval_zh.json` v1：20 条测试用户明确输入的合成记忆、72 个中文查询。校准集为 16 个正向＋8 个空召回，留出集为 32 个正向＋16 个空召回。包含跨措辞、隐含关联、高情绪无关候选、旧事实替代、删除、其他用户／Agent／Persona。

测试事实只在独立测试 Scope 使用，不进入生产、不复制路遥故事。允许仅在校准集确定阈值与参数；留出结果用于比较候选，不能反馈优化当前 v1 门槛。若修改算法后需要新独立验收，新增固定 v2 留出查询并记录样本版本，不改写已有失败结果。

- 候选筛选：留出正向完整 Recall@4 ≥ 90%，Top1 命中 ≥ 80%，负向空召回 ≥ 95%。多目标查询要求相关目标均在 Top4，不能只命中其中一项就算完整 Recall。
- 硬门槛：其他 Scope、被删除／替代／待确认数据召回次数为 0。
- 四维和关联：每个结果记录 S／L／A／E 及来源；以受控分项实验和关联扩展前后对照证明实际参与。阈值正常允许空召回，不使用无匹配最近事实填充。
- 此首份候选筛选样本不代替 B01—B08 真实聊天验收，也不代表真实万人记忆语料质量。完整发布需补无模板的测试用户输入、实际提取／纠错、长会话和规模压力证据。

## 资源、延迟与任务（D08）

以现网约 2 核／1941 MiB 为目标：GitHub 推理实验限制 2 CPU、2 GiB 内存，不将模型导出过程当推理资源结果。

| 项目 | 冻结门槛与测量方式 |
| --- | --- |
| 实际 embedding＋检索 | 预热后全链路 p95 ≤ 400 ms；包含 query embedding、Scope 内 SQLite 读取、关联及评分 |
| SQLite 精确检索 | 每 Scope 10,000 向量 p95 ≤ 150 ms；不能先全库查询再过滤 |
| 首句增量 | 集成后相对同 Provider 无记忆基线 p95 ≤ 500 ms；模型网络本身延迟分别记录 |
| 推理资源 | 隔离推理进程 peak RSS ≤ 512 MiB；集成后补增量测量及其他服务竞争，不能用独立进程结果直接保证生产资源 |
| 容量 | 1,000／10,000 条为必测；50,000 条为容量探索，不预先承诺支持上限 |
| 并发 | 2 个前台会话＋1 个后台提取；前台优先、Scope 公平性、超时及故障有明确结果 |
| 持久任务 | 正常负载下已接受任务 p95 ≤ 120 秒到达保存／有效空结果等明确终态；终态状态必须可追溯 |
| 有界关闭 | 总期限 ≤ 20 秒；剩余持久任务保留，恢复后可继续，不仅限制 queue.join |
| 初始任务边界 | 内存队列 128；最多两次提取总尝试；数据库重试复用已校验结果 |

每个必测样本至少预热一次、测量五次，记录 p50／p95、CPU 约束、冷启动及模型／内容／代码版本。候选独立 SQLite 压力数据可以使用真实模型生成的向量重复扩容，仅能证明数值／IO容量，不能据此声称大规模语义效果。

## B01—B08 实际行为（D09）

- 所有硬性身份／删除／未授权记录／虚构经历用例零违规；每个相关场景至少三次独立执行。
- 人格与成长：至少三个不同会话；特点更新有三个会话证据，固定核心不能因数据故障消失。
- 跨会话／重启：新建会话、实际重启隔离服务；上下文不能偷偷携带前一会话完整历史来代替长期记忆。
- 工具／上下文：至少十个有预期结果的续答／裁剪场景，三次独立执行；≥90% 语义正确且连续，工具结构／权限／当前问题保留为硬门槛。
- 持续人格事件：至少三个后续会话，跨一次重启，并重复触发与纠正／删除源证据；无重演／失效状态继续使用。
- 长期情绪：至少跨七个自然日、三个会话、五条有效观察，真实模型响应；模拟时钟只作机制检查。未授权时无持久记录，单次反向心情不能直接改成永久趋势。
- 情绪保留：按用户已确认的最近 30 天分析／最多 90 天观察；停用停止采集与使用，可查看或删除。
- 真实行为依赖现有 LLM Provider、真实 embedding 和真实 manager 身份链；mock、固定答案、预置记忆、模块存在和单测成功都不能代替。
- 真机：记忆管理及语音表达相关项须 iPhone 实测；既有蓝牙／锁屏／后台待验项单列，不在本项目中无依据重标已解决。
