具体值得沿用的机制及实现边界：

- `config.py`把自己的选择、持续陪伴和自然回忆写入稳定人设，空召回也有明确说明。Mia已有亲近表达、感受／偏好／陪伴承诺和空召回状态；不恢复强制AI声明、意识禁令或泛夸打分。
- `persona.py`在同一流式回复中按完整短句检查、投递；`service.py`先检索、回复后再入队提取。Mia继续使用原回复／语音链和持久Worker；这不是另起一个“多Agent”回复系统的理由。
- `memory.py:rank_memory_candidates`实际使用语义0.58、字面0.28、触发关联0.08、重要性0.06；`expand_memory_query`另有固定联想组。四类信号的思路值得参考，但不能把固定联想组说成从用户对话自动学会的关联，也不因此更改Mia已经冻结的检索参数。
- `MemoryWorkerAgent.start`会写入benchmark预置剧情；提取器还会丢弃重要性低于5的记录。Mia不导入这套专属人物往事，也继续保存普通长期偏好。当前Mia真实模型元数据缺失仍需修复，不能用上游默认重要性或预置线索填出通过结果。
- 上游后台队列是进程内`asyncio.Queue`，停机先等待20秒，之后仍等待放入哨兵和任务结束。源码不提供崩溃后持久恢复保证，也不能据此声称完整停机耗时有20秒硬上限。Mia保留现有持久任务与删除／重启失效机制。
- 上游所读`test_service.py`使用FakeMemory／FakePersona验证编排，不能作为真实模型自然度或记忆准确率证明。PRD中的隐性情绪追踪愿景也不能替代运行源码和真实行为证据。
