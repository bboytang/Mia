# P19／P20 人格事件与授权情绪趋势

当前：实现与验证进行中，不据机制测试提前标为完成。用户目标是完成P19—P20；P20的跨七真实自然日要求保持，模拟时钟仅验证算法。

## 实现

沿用单SQLite事实库、PersonaAgent／ContextBuilder、既有选中Provider和同一MemoryWorker。schema-v3仅增加事件互动证据、观察元数据及版本／撤销触发器；旧表和v1／v2迁移不改，缺失旧来源元数据不补造。

事件分continuity、boundary、reflection。连续性／立场反思需要本轮真实输入与同Scope当前有效事实；明确互动边界来自本轮真实请求。单个身份／依赖关键词不触发。生成前pending候选可影响有界表达，记录实际用户来源；只有完成且通过检查的真实助手输出支持该互动，且Scope／事实／上下文版本仍有效时才active。异常、打断、未知、拒绝和已变化的证据不激活。状态及有限来源持久恢复；幂等键按Scope、事件类型与证据身份，重复追问读取active而不重演固定剧情。纠正／删除来源使状态及片段失效；管理可删除事件。按所选事实直接查询对应事件；单上下文最多4事件，保持现有Token预算与固定核心。

情绪默认关闭。任务接收时记录服务端授权版本，执行与提交复查，不能用之后的启用授权追认先前输入。仅取真实用户完整片段，明确自述与推断分开，推断置信度上限0.6；引用／他人／假设、Mia表情及记忆重要性不算观察。每消息最多一条，观察时间来自真实服务端接收时间，不接受模型或客户端日期。停用停止采集和回复使用；已有观察可查看或删除。纠正、删除、清空、撤权及来源变化使旧上下文失效，在途任务不得复活。

趋势是当前有效观察的即时派生聚合，不持久复制另一套权威结果。最近30个UTC自然日分析、最多90个UTC自然日保留。自述与推断分别满足五观察、三会话、跨七自然日，分别列数量、分布、近七日与更早变化、置信度及有界证据ID，不混池制造样本量；不足明确insufficient_observations。只在相关问题且授权有效时进入上下文，不把历史趋势替代当前感受或医学诊断。修正／删除后由剩余有效证据重算；Worker周期清理过期观察。

必要后端操作沿用`mia_memory`／request_id与可信Scope：`events`、`event_delete`、`emotion_consent(enabled)`、`emotion_status`、`observations`、`observation_update(id,tendency)`、`observation_delete(id)`、`emotion_clear`。P21客户端展示和确认说明另行完成；本步不改聊天UI、端口或生产服务。

## 验证入口与边界

服务单测覆盖持久恢复、真实完成钩子、失败不激活、幂等、证据删除／纠正、跨Scope、默认关闭、授权版本竞态、观察来源／否定、分组门槛、单次反向、不相关上下文、跨连接停用、修正／删除重算、保留期及迁移回滚。时钟、策略与向量在单测中为明确标注的夹具。

原安装SDK＋实际BGE的受控job检查事件pending→active、重开DB／新会话／重复／删除，以及模拟跨日观察、相关上下文和停用；原P12—P18回归继续。实际manager TLS／WSS验证事件完成、本人观察／外人拒绝及授权恢复，模型输出和向量在该job为夹具。不能据这些控制场景称八项真实行为通过。

`mia-memory-continuity.yml`只在手动dispatch调用已有GitHub专用测试Provider。dialogue模式最多13次（原10项及三项事先固定的新日常语料）、单次30秒、无重试；每阶段真实新Python进程，记录原始合成测试输入及实际输出。reply bridge使用隔离8192估算预算／256输出，提取768输出；这是小请求测试包络，**不解除生产模型容量与输出预留未核实限制**。向量／策略为夹具，实际BGE及manager另测，完整B05／B07／B08仍由P22验收。

daily模式每实际UTC日追加一条真实接收时间的合成测试自述，禁止伪造时间或同日重复；每次一次真实提取及一次自然对话回复，累计最多7个观察日／14次请求；首个旧版采集run仅做一次提取，其实际证据不改写。后续以`previous_run`指向上次成功daily run，工作流核实同仓库／分支／workflow、成功状态、制品与DB hash，再恢复隔离测试库。每次保留完整运行链、时间和授权／趋势状态。没有在任务分支上伪称已生效的schedule；跨日采集需在实际日期继续dispatch。

若首条真实观察在2026-10-15接收，最早2026-10-21才能跨七个UTC自然日，且仍需五条／三会话及实际对话／变更证据。没有这组真实日期证据时，P20保持未完成，持续目标不缩成“模拟时钟通过”。不使用生产用户数据、模型Key或部署来填补缺项。

用户追加要求：回答自然、像人在聊天，减少AI模板和后台术语。固定核心已补口语、直接回应、用“你”、避免机械开头／客服结尾和未经询问的AI自我说明；明确身份／意识问题仍诚实，不冒充人或编造感受。真实对话增加自然风格检查并逐条阅读原文，不以关键词规则替代语义复核。

用户随后明确希望保留善意的陪伴承诺。当前规则允许“我会一直陪着你”等关系中的安慰，移除该措辞的机械拦截和必附免责声明；技术服务在线、现实行动或共同经历仍按事实回答，不以安慰要求排他依赖。四个基础实际Provider样本分别检查身份、未知事实、自然陪伴及技术在线保证，不以强制拒绝陪伴作为通过标准。
