# P05 数据与行为契约 v1

状态：P05 开发契约完成，D02 采用用户已确认的智控台一次性授权码，私有通信支持可信域名或 IP 证书的 HTTPS/WSS；D05／D06／D07／D10 确定。公网 TLS 实际部署与真实 Java 链安全验收仍未执行，不以契约完成代替运行安全证明。

依据 V1.2、现有 `server/companion`、固定小智 v0.9.7 及 P03 实际组合。仅内部职责与必要扩展，不新建账户／通信／Agent 平台。

## 1. 身份和权限（D02）

保持原设备 ID、client ID、绑定及当前语音凭据格式。私有权限不得由公开 OTA 设备标识或原弱凭据自动取得。

用户已明确选择复用已登录智控台的现有用户／Agent／设备权限，通过一次性授权码授予 App 私有设备凭据。不新增 App 账号登录或第二套账户权威，保留设备 ID 与原绑定。

私有凭据须随机且不可由 MAC／昵称推导，服务端只存必要的凭据散列／权限／版本／撤销状态。签发前、兑换时核实已授权数据归属和当前绑定；授权码使用至少 128 bit 随机量、10 分钟期限、一次性原子消费和每设备／真实来源 5 次失败兑换上限，并有全局有界限流。私有凭据至少 256 bit，默认 30 天，绑定／授权撤销立即失效；续期需有效权限，不能凭过期旧弱 token 续期。凭据保存在现有 Keychain 生命周期，禁止 URL 参数或普通 UserDefaults 存放秘密。

私有读写在现有服务端接口取得可信 Scope；客户端提交的 user／owner／Agent／Persona 只作为待授权选择，不是权限证明。原语音认证和私有数据授权分开判断；不因普通聊天可用而默认开放私有记忆。绑定、重绑、解绑、撤销和到期都必须作用于已建立连接及待提交任务。

目前服务器无 80／443 监听，App 默认明文入口。公网私有凭据及数据必须经已核验 HTTPS／WSS；没有可用入口时继续隔离开发，不能用生产明文传输测试私有凭据来“验收”。域名不是代码前提；可用受信任 IP 证书匹配现有 IP，App 保持平台证书／地址验证。具体证书获取／续期、挑战监听和现有端口上的 TLS 部署在发布方案中核实，不擅自开端口或替换通信体系。IP 证书的 160 小时期限和自动续期依据 [Let's Encrypt 官方说明](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)；目前尚未申请证书。

## 2. AuthenticatedScope 与归属（D10）

内部认证结果至少包含操作者／权限、有效归属用户、Agent、Persona、设备／client、绑定版本、私有凭据状态／版本。不能从客户端字符串构造有效 Scope。

- 原 owner `user:<id>:agent:<id>` 和旧记忆 ID 保留。初期每个已授权 Agent 明确映射 `mia` Persona，不新增多角色 UI。
- 其他 Agent 或 Persona 是独立范围；同用户同 Agent／Persona 多设备可共享，身份和来源不随设备切换丢失。
- 操作者与有效归属可不同，只能经既有管理员授权；不能强行要求所有 ID 相同。
- 所有候选查询先限制 Scope 和有效状态，再做向量／词法／关联操作。缓存键包括 Scope、内容／人格／授权版本。
- 生成前、工具续答前、管理操作前、后台执行与提交前复查相关权限及版本。旧 Scope 不因任务已入队自动继续有效。

## 3. 事实、来源与派生结构（D10）

现有 memories／sources／traits／owners／checkpoints 保留；需要的新增字段优先用扩展表。新写入显式列名，不能直接改旧位置式 INSERT 仍依赖的表形状。

| 对象 | 必要内容与权威边界 |
| --- | --- |
| 事实 | 原 ID／owner／类别／内容／时间；Persona、实体、keywords／trigger_terms、情绪重要性、内容版本、有效状态、明确确认／敏感授权来源 |
| 来源 | 真实用户来源片段、稳定 Session／Turn／Message、时间、来源类型、原指纹和关联记忆；不把模型回答当用户事实 |
| 向量 | 事实 ID／Scope、模型／revision／维度、内容版本、归一化向量；是可重建派生数据，不是第二份权威内容 |
| 特点 | 现有 traits，至少三会话真实证据、版本、一次最多一个特点更新；删除依据须失效 |
| 任务 | 幂等键、来源、Scope／绑定／授权／记忆版本、状态、尝试数、经校验结果、期限及错误类别 |
| 事件 | 类型、资格／状态、真实来源与记忆版本、幂等键、时间、有限表达影响；不修改固定核心 |
| 观察／趋势 | 对象、事件／观察时间、来源、自述／推断、倾向／置信度、授权版本、聚合窗口与证据版本 |

事实状态区分 active／pending／superseded／invalidated。旧 confirmed 不重新解释为用户亲自确认；缺失元数据不补造。`content` 与提取 `context_summary` 只有一份权威映射。

明确纠正、随时间变化与不确定冲突分开处理；向量相似度只提供候选，不决定事实覆盖。删除／清空让相关向量、来源、特点、任务、事件、趋势和缓存按作用范围失效；暂停停止提取不等于删除。

版本变化与幂等按事务处理。在途任务因删除／解绑／撤权取消时有明确终态；不得为了完成“已接收任务”而写回被用户撤销的内容。

## 4. 历史和 ContextBundle（D05）

默认不新增持久完整聊天。会话内保留既有最多 20 个完整用户轮次，并进一步遵守 Token 预算；跨会话由必要事实、事件、特点和授权趋势保持连续，不把旧完整消息秘密携入新会话。

必要来源片段沿用当前每段最多 512 字符；随相关记忆和证据生命周期保存，用户删除／清空时处理派生影响。原始音频不为记忆新增长期保存。不会恢复完整聊天的设置与版本不得宣称完整历史恢复。

ContextBundle：Scope、Turn、输入、人格版本、合法历史／工具消息、RAG／revision、有效事件、授权相关趋势、可选场景、安全决定和预算。固定规则与不可信材料分开，材料不能变成工具授权。

用户已确认：相关事实可以被召回，但不足以回答所问属性时，PersonaAgent 必须明确未知，不推断。现居城市不能证明出生地；朋友职业不能证明年龄。真正无关问题仍要求空召回，相关不可回答单列真实响应验收。

预算由实际 Provider 的上下文上限、现有响应上限和工具定义共同决定，不根据模型名字猜容量。优先使用可核实的 tokenizer；缺 tokenizer 时按 UTF-8 字节与协议结构作保守上界并明确记录计数方式，不能伪称精确 token 计数。固定核心、当前问题和完整工具结构优先，再放相关事实／近期历史；趋势和旧材料按相关性裁剪。

输入预算上限初始 8192，受实际已核实 Provider 总窗口减响应预留的更小值约束。没有核实容量或无法保留必须结构时，返回明确限制状态／请求缩小本轮任务，不能提交超预算输入或拆坏工具结构。输出预留使用已配置 LLM 参数，不擅改现有模型／费用设置。

同轮工具续答复用快照；再次生成前权限／revision 改变则重建，解绑／撤权拒绝私有材料。最终输出前做有界增量检查，最终全量检查只作补充，不能撤回已经播放内容。

## 5. 持久任务与结构提取（D10）

SQLite 持久接收成功后才称任务已接收；事实事务提交成功才称已记住。内存队列只是加速调度，不作为持久权威。

状态：pending → extracting → validated → committed／empty；失败按模型／解析／数据库分类，必要时 retry_wait → 相应阶段；用户操作取消为 cancelled，尝试耗尽为 failed。空 JSON 合法结果与 JSON 非法不同，后者不能假称 empty。

初始队列 128，服务级后台并发 1、前台优先、Scope 公平；两次提取总尝试。经校验结果持久化后数据库重试不重复请求模型。关闭总期限 20 秒，任务未终结仍持久可恢复。

统一 TurnCompleted 覆盖正常回复、direct_answer 和工具终结，所有路径使用稳定幂等标识，重复钩子不能重复写事实。提取保留显性事实和有真实来源的隐性线索；低情绪但长期有价值信息不能被情绪门槛直接丢弃。

来源、敏感候选、秘密过滤、实际 Scope、暂停／revision／绑定／授权在执行和提交时复查。队列满和过载有明确状态，不能静默丢弃或在前台无限等待。

## 6. 持续人格事件（D06）

首批事件仅为实际连续性需求：有记忆来源的连续性确认、用户明确互动边界的确认、有双方实际交流证据的角色立场反思。不是固定剧情，也不表示主观意识。

资格须来自真实当前互动＋有效支持证据，单个“你是谁／你会离开吗”关键词不足。状态 eligible／pending／active／invalidated；回复前判断资格并支持本轮有限表达，实际完成互动后确认持久状态。输出失败或没有发生的互动不能伪记为 active。

幂等键由 Scope、事件类型及稳定证据身份构成；重复追问读取有效状态，不重复演剧情。表达影响限于回应方式，不改固定核心、权限或证据驱动特点成长规则。证据被替代／删除后重评或失效，版本化结果进入 ContextBundle。

## 7. 授权观察和趋势（D07）

用户已确认：默认关闭；启用后分析最近 30 天，观察最多保留 90 天；停用停止采集与使用，可保留供查看或选择删除。删除、清空和撤权仍需作用于派生记录与缓存。

只记录有真实来源的用户情绪观察；区分明确自述／推断及被观察对象。别人的情绪、引用、Mia 表情、记忆 emotional_weight 不等于用户情绪。推断单独标记；不据单轮情绪制造永久特点。

形成长期趋势的最低资格为窗口内五条有效观察、至少三个会话且跨七自然日；不足时明确“观察不足”，可以临时回应当前情绪，但不能声称已有长期趋势。

聚合先按对象／时间／来源和有效性筛选，分别报告自述与推断的数量、倾向分布、相关证据及最近变化；不把预测分数描述为用户真实感受的测量。PersonaAgent 仅使用与本轮相关、授权有效的结果，不新增 Emotion Agent 或第二次回复生成。

来源纠正／删除后使旧聚合失效并重算。过期观察在维护任务中清理，派生数据与缓存同步；停用保留的观察只能供用户查看，不能继续用于回应或成长。

## 8. 接口、兼容和剩余条件

保留 `mia_memory`／request_id／action，必要操作版本化、响应有界；状态区分接收、保存、待确认和失败。继续既有管理 UI，只补必要事件／趋势操作。

目前本文没有实施这些契约，没有新的 schema 或生产变更。D02 用户入口已确认、TLS 必要行为已确定；具体证书／网络发布留在发布前核实。真实 Provider 容量／测试权限需要核实，D03／D04 等待 P06。实际身份安全验收在 P08，不因 P05 契约完成提前标通过。
