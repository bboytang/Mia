# P18 纠错与维护

当前实现待 GitHub Actions 验证，不能据代码存在标为完成。

沿用 P17 提取器、Worker 和唯一事实库，无 schema 变更。自动协调必须同时具备同归属有效目标、完整旧事实引文、实际用户新句、明确分类及内容／证据版本。当前保守支持 `更正：旧事实；新事实`、`以前：旧事实；现在：新事实`、`不确定：旧事实；新事实`。其他自然表达不自动覆盖，可由现有管理入口明确修改；任意中文语义纠错不据此宣称通过。引用／假设和模型自行指定 replaces_id 不允许覆盖；同批不得两次改同目标或使用正在改变的关联／特点依据。

明确纠正更新同一事实 ID 并撤销旧来源；时间变化保留旧事实及来源，将旧记录标为 superseded／未确认，当前召回只使用新事实；冲突双方进入待确认，均不作为当前事实。当前待确认沿用既有 confirmed 与候选管理，P21 展示确认理由仍待后续。敏感或推断内容不得自动替换旧事实。

协调提交在同一事务复查目标版本，更新事实、BGE 向量及元数据，失效关联／特点／事件／观察、推进 revision 并取消其他旧任务；编码或 DB 失败复用已校验结果。观察通过来源消息身份或完整来源内容定位，清除失效观察的 excerpt 并推进 observation_epoch；尚无 P20 聚合实现，不声称已重算趋势。清空删除同归属事件及观察；暂停保留事实与向量，停止提取并取消旧任务。

跨连接使用现有 revision／content_epoch 检查，在下一轮清历史、工具续答重建和流式输出前拒绝旧快照，不重放工具副作用。已经发出的文本或音频无法撤回。已有删除／清空／暂停／编辑竞态回归继续执行，新增协调任务编码中删除／清空／暂停／撤权和校验后目标证据变化。

验证入口：服务维护单测；已安装上游 SDK＋真实 BGE 的三种协调、DB 事务回滚重试及第二 SQLite 连接缓存；实际 manager 身份／TLS／Scope 和 Java 回归。模型输出为合成控制夹具，非真实 Provider 中文语义／完整 B03、八项行为、全服务负载或真机验收。自动化全部在 GitHub，生产容量限制不改，不部署。
