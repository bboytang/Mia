## 已核实的缺口

固定 v0.9.7 中，report 按 MAC 查询**当前** Agent；旧连接排队后重新绑定可能把旧内容归到新 Agent。标题／摘要只凭 server-secret 和 session ID 请求，后台任务不复查私有授权；摘要保存目标还从设备当前绑定推导。这些是本次必要认证／授权／绑定／撤销链的组成部分。

## 最小修改

- 保留原队列、音频转换、聊天记录、标题与摘要生成机制，不另建账户／通信或聊天系统。
- report 附带已验证的六字段 Scope 快照，不带授权码或私有凭据；服务端校验当前 owner、operator、设备、client、绑定及凭据版本。原 MAC 与 Scope 不符、session 内有其他 Agent／设备记录、缺快照一律拒绝。
- 标题／摘要传递同一快照，接收及任务执行前复查，固定原授权 Agent；模型返回后再以短数据库事务复查并写入。复用绑定／撤销的 device→grant 锁顺序，模型调用期间不持锁。撤销／重新绑定先完成时结果丢弃，写入先完成时随后撤销生效。
- Python 复用原 manager client 的 server-secret、一次有界请求；身份检查／上报3秒，既有同步标题请求30秒，不使用旧六次重试。音频／正文格式不变。
- 必要上游文件均检查固定 SHA、完整备份；不在生产运行安装器。新增 Spring 授权辅助只服务已有三个写入口。
